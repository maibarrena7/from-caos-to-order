“En mi compu funciona”

setwd("C:/Users/usuario/Desktop/nota plantas")
datos <- read_excel("Datos_campo_plantas_COMPLETO.xlsx", skip = 1)

En cualquier otra computadora:

Error in setwd("C:/Users/usuario/Desktop/nota plantas"):
  cannot change working directory

Y en tu misma computadora, si movés la carpeta o cambiás de compu, también.

Preguntar: ¿alguna vez les pasó? Clásico al pasarle el script al director/a.

setwd() con una ruta absoluta ata el código a una computadora y a una ubicación. Es el problema más común cuando alguien intenta reproducir un análisis.

Proyectos de RStudio

Un archivo .Rproj en la raíz de la carpeta del proyecto.

Al abrirlo, RStudio:

  • ubica el directorio de trabajo en esa carpeta, automáticamente
  • recuerda los scripts abiertos y la configuración de ese proyecto
  • separa un proyecto de otro

Un proyecto = una carpeta = un .Rproj.

Basado en LMU Open Science Center, Introduction to Version Control within RStudio, sección “Creating an RStudio project” (CC BY-SA 4.0); Bryan, J. (2017). Project-oriented workflow. Tidyverse blog.

Demostración en vivo: File → New Project → Existing Directory. Mostrar que getwd() da la carpeta del proyecto.

En el proyecto de ejemplo hay DOS .Rproj sueltos en subcarpetas: preguntar qué problema genera eso.

Rutas relativas con here()

here::here()
#> "C:/Users/maite/Documents/visitantes-florales"   ← en mi compu
#> "/home/juan/proyectos/visitantes-florales"       ← en la de Juan

datos <- readxl::read_excel(here::here("data", "raw", "2023-03_campo_plantas.xlsx"))

here() arma la ruta desde la raíz del proyecto, esté donde esté la carpeta y en el sistema operativo que sea.

Müller, K. (2020). here: A Simpler Way to Find Your Files. R package. https://here.r-lib.org

Ventaja extra: funciona igual en Windows, macOS y Linux (las barras / y ).

Funciona aunque el script esté en una subcarpeta (R/), porque busca el .Rproj hacia arriba.

El workspace no es el proyecto

.RData guarda los objetos de la sesión. Parece cómodo… pero:

  • tus resultados dependen de cosas que no están en el código
  • objetos viejos se cuelan en análisis nuevos
  • nadie más puede reconstruirlos

El código es la fuente. Los objetos se recrean corriendo el código.

Tools → Global Options → General

  • Save workspace to .RData on exit: Never

Hacerlo todos juntos ahora, en vivo. Es un cambio de 30 segundos que previene muchos problemas.

Atajo para “empezar de cero”: Session → Restart R (Ctrl/Cmd + Shift + F10).

Tampoco adentro del script

install.packages("ggplot2")        # ✗ se reinstala cada vez que alguien lo corre
ggplot2::ggplot(datos, ...)        # ✓ esto sí: paquete::función()

Los paquetes se instalan una vez, desde la consola. En el script se usan con paquete::función(), así queda claro de dónde sale cada función.

Las instrucciones de instalación van en el README (encuentro 3).

La mudanza

Mudanza guiada

Individual o en parejas 35 min

Con la guía de mudanza de la página del encuentro:

  1. Crear el .Rproj en la raíz de la estructura del encuentro 1
  2. Elegir el Excel crudo, renombrarlo y moverlo a data/raw/ como solo lectura
  3. Mover cada archivo a su carpeta… o descartarlo
  4. Borrar .RData, .Rhistory y los .Rproj sueltos

Fase P, la más larga. Circular. La guía es una propuesta: si alguien decide distinto con un buen argumento, perfecto.

Solo lectura: Windows → clic derecho → Propiedades → Solo lectura. macOS → Obtener información → Bloqueado.

Decisiones difíciles

Archivo ¿Qué hacemos?

analisis_prevalencia.R y ..._v2_OK.R ¿Cuál es el bueno? No lo sabemos

Esta slide se discute DESPUÉS de la actividad, no antes.

Lo importante: cada duda que no podemos resolver es información que faltó documentar. La anotamos para el README del encuentro 3.

¿Corre?

Individual 15 min

Abrí R/analisis_prevalencia.R desde el proyecto y:

  1. Borrá la línea de setwd() (y cualquier install.packages(), si hubiera)
  2. Cambiá la lectura de datos y el ggsave() por:
datos <- readxl::read_excel(
  here::here("data", "raw", "2023-03_campo_plantas.xlsx"),
  skip = 1
)

ggplot2::ggsave(here::here("outputs", "figuras", "grafico_prevalencia.png"))

Es el único cambio de código del encuentro, y se los doy hecho.

Si alguien no tiene here: install.packages(“here”) en la consola (¡no en el script!).
