Control de versiones

En lugar de copias del archivo…

informe_v1.docx  informe_v2.docx  informe_final.docx  informe_final_ok.docx

… un solo archivo con su historia:

● 2026-12-03  Agrego la figura 2               (Maité)
● 2026-12-02  Corrijo la unidad de la altura   (Maité)
● 2026-12-01  Primera versión del análisis     (Maité)

Cada punto es una foto del proyecto, con fecha, autor y un mensaje. Podés volver a cualquiera.

Basado en Von Grebmer zu Wolfsthurn, S., Edelsbrunner, P., Ihle, M. & Schönbrodt, F. (2026). Introduction to version control with Git in RStudio [Quarto slides]. LMU Open Science Center (CC BY-SA 4.0).

Git y GitHub no son lo mismo

Git

  • Un programa en tu computadora
  • Registra los cambios de una carpeta
  • Funciona sin internet

GitHub

  • Una página web
  • Guarda una copia del repositorio en la nube
  • Sirve para respaldar, colaborar y compartir

Git es como el programa que saca las fotos; GitHub, como el álbum compartido en la nube.

Vocabulario mínimo

Palabra Qué es
Repositorio Una carpeta cuyo historial está registrado por Git
Commit Una “foto” del proyecto, con un mensaje que dice qué cambió
Historial La lista de todos los commits
Push Subir los commits de tu compu a GitHub
Pull Bajar a tu compu los commits que están en GitHub
.gitignore La lista de archivos que Git no debe registrar

Basado en LMU Open Science Center, Introduction to version control with Git in RStudio (CC BY-SA 4.0).

¿Qué NO va a un repositorio?

Discusión 10 min

En desordenado/ había un archivo CONVENIO_permiso_colecta_FIRMADO.docx.

¿Lo subirías a GitHub? ¿Qué otros archivos no deberían ir?

Llegar a la lista: datos personales o sensibles (convenios, DNI, datos de participantes), archivos muy pesados (fotos, videos, datos crudos enormes), productos que se regeneran (outputs/, data/processed/), archivos de sesión (.RData, .Rhistory), contraseñas o tokens.

Aclarar: un repositorio privado tampoco es lugar para documentos sensibles.

El .gitignore

# Archivos de sesión de R
.Rhistory
.RData
.Rproj.user/

# Productos que se regeneran con el código
data/processed/
outputs/

# Documentos con datos personales: nunca
*FIRMADO*

Un archivo de texto en la raíz del proyecto. Cada línea = algo que Git ignora.

Ojo: el .gitignore no “borra” nada, solo hace que Git no lo registre. Y hay que crearlo ANTES del primer commit: si un archivo ya fue registrado, ignorarlo después no lo saca del historial.

Manos a la obra

Primer repositorio

Guiado, paso a paso 30 min

  1. Guardar la plantilla como .gitignore en la raíz del proyecto
  2. GitHub Desktop → File → Add local repository → elegir la carpeta → create a repository
  3. Primer commit: “Proyecto organizado”
  4. Cambiar algo en el README.md → segundo commit
  5. Mirar el historial (History)
  6. Deshacer un cambio (Revert changes in commit)

Demostración en vivo con proyector, paso a paso, y que lo repliquen. Ir al ritmo del más lento: en la encuesta de inscripción vimos quién nunca usó Git.

Alternativa para quien prefiera: pestaña Git de RStudio (requiere Git instalado aparte). GitHub Desktop trae Git incluido.

Buenos mensajes de commit

Así no Así sí
cambios Unifico los nombres de los sitios en la limpieza
asdf Corrijo la unidad de altura en el diccionario
final Agrego la figura 2 (prevalencia por sitio)

El mensaje responde: ¿qué cambió y por qué? Lo va a leer tu “yo” de dentro de seis meses.

Subir a GitHub

Si llegamos 10 min

  1. En GitHub Desktop: Publish repository
  2. Dejar tildado Keep this code private
  3. Entrar a github.com y ver el proyecto (¡con el README como portada!)

Si no da el tiempo o falla internet, hacerlo como demostración. Se retoma en el encuentro 6 para la revisión cruzada.

Para la próxima

Tarea ≤ 30 min

Hacé al menos un commit más en el proyecto, con un mensaje claro. Si lo publicaste, hacé también Push.
